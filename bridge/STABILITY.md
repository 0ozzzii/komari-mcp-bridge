# 长连接与本轮稳定性修复

日期：2026-10-06（Asia/Shanghai）。仅本地开发、隔离验证；没有升级、重启用户面板或替换线上探针。

采用已确认的生命周期：**监控持续保活，终端按工作会话建立并复用**。MCP 请求结束、客户端关闭或退出 stdio 适配进程，都不默认关闭 daemon 持有的终端。活跃或结果未明的命令不按普通空闲策略回收。

## 连接及开销

| 链路 | 原有行为 | 本轮补充 |
| --- | --- | --- |
| 探针监控/事件 → 面板 | 持续 WebSocket；30 秒 Ping、上报、重连；HTTP POST 回退；面板 75 秒读期限 | 探针增加 75 秒读/Pong 期限；监控数据写入限时 10 秒；关闭不再等待阻塞的写锁 |
| 桥接 → 面板管理员终端 | 新增桥接原已有 20 秒 Ping、75 秒读期限、5 秒写期限 | 增加 `last_admin_pong` 和脱敏错误分类；等待探针和 shell READY 可配置 `CONNECTION_READY_TIMEOUT`，默认 60 秒 |
| 探针 → 面板独立终端 | 原有独立 WebSocket、PTY 和 5 分钟保留；终端自身没有周期 Ping/Pong 失联检测 | 面板两侧与探针终端分别增加 20 秒 Ping / 75 秒读期限 / 5 秒写期限；不向 shell 注入空行 |

以上是工程默认值，不是实际代理超时的调查结论。代理须转发 Authorization、Upgrade 并允许该生命周期；同机部署应配置内部地址，否则公共域名仍可能绕经外部代理。

若有 N 个节点、S 个打开的工作会话，原有 N 条监控连接继续使用；额外终端约为 **2S 条 WebSocket 和 S 个 shell/PTY**。没有工作会话的节点不会因 MCP 功能预建 shell。心跳通常是很小的控制帧，不创建命令子进程；实际 CPU、常驻内存和 TLS/代理开销需在目标环境测量，当前没有生产性能数据。

更需要限制的是 shell 数量和输出存储：桥接默认每会话 2 MiB 内存输出上限、单调用方 8 个会话、总计 64 个会话；磁盘日志也有上限与保留期。后台任务与 shell 内部进程的资源不由这组缓存上限限制。

## 从源码定位到的风险

面板基线 `202579014bf9670350a673ba91c240174805c9a0`；复核官方 `39cb3f59b2837e8d052203bfbbf3187888e5fa4c` 的相关原终端文件相同。探针基线 `828afafe7fb5b1b58c1232094e1e46320719016e`。用户线上版本、网络和代理仍未知，不能据此认定频繁掉线的唯一原因。

| 文件/路径 | 风险与处理 |
| --- | --- |
| `web/api/terminal/forward.go` | 原浏览器 JSON heartbeat 被消费，不保护第二段连接，也不产生反向控制流量。保留此兼容语义，新增 WebSocket 协议 Ping/Pong，避免将 JSON ACK 显示成终端输出。结束转发时关闭旧双端连接并等待旧 reader 退出。 |
| `web/api/terminal/terminal.go` | 替换一侧连接可能让旧 reader 与新 reader 共用另一侧 WebSocket。现在淘汰旧双端网络连接，随后重新附着 PTY；清理回调检查代次，旧转发器不能关闭新会话。 |
| `web/connection/safe_conn.go` | 原 Close 与数据写入共享互斥锁，慢写阻塞关闭。分开元数据锁和写锁，先关闭底层连接，限时写；Gorilla 允许控制帧与数据写并发。监控和终端分别设置写期限。 |
| `agent-patches/0002-connection-stability.patch` | 探针监控和终端补充保活、限时写、旧连接所有权与保留计时器代次检查；输入写失败明确断开，EOF 前最后一批输出仍转发；Unix 关闭 PTY fd，不再向可能阻塞的程序注入退出文本。 |

这不是重写网关或探针：新增 daemon、管理入口、工具和策略；在原终端/连接代码上做有限修复；探针以可审查补丁交付。RHMCP 与 CF-MCP-HUB 没有被修改，65 个参考工具也没有整体塞入探针。

## 故障兜底与边界

| 场景 | 真实行为 |
| --- | --- |
| AI ↔ 桥接断开 | daemon 持续读上游；已收到的输出保留在受限缓存/日志，后续游标继续读。 |
| 任一终端网络段断开 | 单个重连流程，500 ms 起、最大 15 秒、带抖动、最多 4 分 30 秒；不自动重发任意命令。输出可能丢失，返回 `output_gap`。 |
| 相同 request_id 重连 | 空闲 shell 用 nonce + PID 校验；运行中或结果未明时不自动向程序注入校验命令。相同 ID 本身不能证明上下文保留。 |
| 已派发但未收到 END | 标记执行不确定；command_id 重试返回已有记录，不派发第二次。没有远端去重协议，不能保证端到端恰好一次。 |
| 没有日志或仅收到 Pong | 不当作命令结束。`last_admin_pong` 只证明管理员侧传输活跃，不证明探针/PTY 或命令正常。 |
| 停止等待 / Ctrl+C / 关闭 | 分别是工具返回、中断请求和会话关闭；没有原生销毁 ACK，不声称强制终止已确认。工具 wait 超时不自动杀任务。 |

探针仍持续排空 PTY，断线输出仍会丢弃；桥接不能补回没收到的字节。此次没有增加探针日志回放、输出序号协议或可靠远端命令去重。超过保留窗口、面板或探针重启不能承诺恢复原 shell。任意 TUI、raw mode、超大输入、后台进程输出归属也不是第一版保证：PTY 写入遇到不消费输入的程序仍可能阻塞，保活不能替代完善的输入背压协议。
