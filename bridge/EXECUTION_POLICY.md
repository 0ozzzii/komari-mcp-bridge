# 执行策略与基础资源保护

这是 MCP 增量功能，配置只放在原后台 MCP 页的「执行策略」弹窗。没有修改其他管理页面，没有安装 SSH、取消认证或加入新的被控端守护程序。必须同时使用含本轮增量的面板、桥接和探针；旧探针缺少保护协议时，受管理终端不会被报告为就绪。

## 默认值与适用边界

| 有效内存容量 | 单设备普通槽位硬上限 |
| --- | --- |
| 不足 1 GiB | 5 |
| 1～2 GiB | 8 |
| 2～3 GiB | 10 |
| 3 GiB 及以上 | 12 |
| 资源未知／面板报告过期 | 桥接暂按 1；新探针就绪后返回自己的资源 |

容器沿用已有 cgroup v1/v2 和祖先限额统计，不用宿主机总内存。未知配额不虚构成 512 MB。自动档位按有效容量，不按一瞬间空闲容量跳变；内存余量低于 10% 时另行暂停新增普通执行。working-set 与传统 used 都只是内存压力近似值，不能保证任何一个编译、安装任务都不会 OOM。

一个槽位代表一个尚存活的 PTY／shell 或一个官方 `task/exec` 任务，**并非限制任意子进程数，也不是每槽预留固定内存**。空闲但未关闭的 shell 仍计数；断线保留期内仍计数；租约到期不释放运行中的占用。不同 Key、不同工作会话与人工网页终端在探针侧共用单设备上限，不能各自拿满一份。桥接中的 Key 上限是每个节点的限额；桥接另外保留全局 64 个会话与每 Key 64 个会话的防止无限创建上限。同一工作策略可用不同 `session_name` 建多个独立 shell；单 shell 仍只跑一个普通前台命令。

管理员可配置默认策略、单设备覆盖和单 Key 限制。Key 只能在设备限制内收紧。新的准入立即使用桥接新策略；在线受管理终端收到配置推送，`remote_policy_revision` 表示探针确认的版本；未连接设备在下一次工作会话接入时同步。老连接携带的旧版本不能把探针策略改回去。没有工作终端接入过的探针，其官方任务使用内置默认值；本轮没有增加监控 RPC 配置下发。配置降低不会杀掉现有会话，超过新上限时拒绝新派发，先关闭多余空闲会话。

## AI 的使用流程

MCP `initialize.instructions` 提供一次简短规则；`tools/list` 的参数说明也写明期限。AI 无论是否采纳提示，普通执行都受代码准入约束。

1. `komari_nodes_list`：返回授权节点、资源、硬上限和默认串行建议。
2. `komari_execution_policy`：`action=inspect` 查看限制；`action=set` 以 `node_uuid`、`work_id`、`parallel` 协商当前工作策略。AI 只能降低到管理员上限内，不能修改设备或 Key 的永久配置。
3. `komari_session_open`：同一调用方／节点／工作／`session_name` 复用 shell。省略 `session_name` 为 `main`。
4. `komari_command_run`：提供 `command_id` 与命令；长任务在派发前显式填写 `execution_timeout_ms`。通过 `komari_output_read` 按游标继续跟进。
5. `komari_command_interrupt`／`komari_session_close`：必要时明确中断或释放，任务完成后关闭不用的会话。

工作策略默认有效 10 分钟。初次协商／显式重新协商建立期限；之后只有**成功发送的新命令或非空交互输入**续期。桥接能确认的是网络写入已被接受，不能把它说成远端已开始执行。状态查询、读日志、输出流、Ping/Pong、resize、Ctrl+C、重复 `command_id` 都不续期。到期后查询、中断、关闭仍可用，普通新执行需重新协商；正在跑的命令不会因此被杀。桥接重启不恢复授权租约，须重新协商，仍保留原命令记录，禁止自动重跑。

相同 `command_id` 和相同文本返回已有记录，不重发、不延长命令期限；不同文本是冲突。终端字节流没有远端持久去重，仍不承诺跨任意故障「恰好执行一次」。不因结果未知自动执行安装、迁移等有副作用命令。

## 命令期限与维护

| 配置／动作 | 默认行为 |
| --- | --- |
| 普通受管理命令期限 | 30 分钟 |
| 显式长任务上限 | 6 小时，管理员可调整；AI 可缩短或在该上限内延长 |
| 工具等待 | 0～10 秒，与命令期限分开 |
| 空闲会话回收 | 30 分钟，仅没有未完成命令的会话 |
| 独立维护槽位 | 每节点最多 1；默认关闭，需要设备／默认与 Key 两侧授权 |
| 维护会话总期限 | 15 分钟，从创建起计，不因调用续期；维护命令期限也不得超过该值，不作为普通长任务通道 |
| 超时加强关闭 | 默认关闭；设备与 Key 两侧授权后，SIGINT 请求后 10 秒仍没有结束确认才关闭该 PTY |

长任务示例：`execution_timeout_ms: 14400000` 表示 4 小时。必须在首次派发前指定；修改重试请求中的数值不会延长已运行命令。

探针先确认已装配命令期限，桥接才发送实际 shell 命令。计时器在探针进程内，管理员侧／探针侧终端 WebSocket 中断不会取消它。Unix 向 PTY 的当前前台进程组请求 SIGINT；原终端交互 `Ctrl+C` 仍是发送控制字节。收到真实 END 标记才能确认正常退出码；没有 END 则报告 `timeout_unconfirmed` 或 `uncertain`，不能编造 0。SIGINT 可能被忽略，原始交互程序／后台脱离进程不保证被停止；探针进程重启也不能承诺计时器继续存活。当前受管理持续 shell 支持范围仍为 Linux POSIX `/bin/sh`，Windows 交叉构建通过不等于实现 PowerShell 持续状态与完整进程树管理。

普通槽位满或内存压力时，已有会话的状态、读输出、中断、关闭仍可用。HTTP 层给中断、关闭和即时会话状态保留独立有界容量（全局 8／每 Key 2），普通输出长轮询不能耗尽它。维护通道可在普通槽位满时建立，但它仍执行任意 shell，因此必须由可信 Key 使用、单节点一个且限时；它不是语法白名单或权限降级，不能指望用它安全地运行任意不可信命令。

## 官方任务、输出与诊断

官方 `task/exec` 路径也接入同一探针槽位池。默认 30 分钟期限、最多保存 2 MiB stdout+stderr 合计；超过上限的输出继续排空并标注截断，不阻塞子程序。Unix 对该任务自己创建的进程组取消，Windows 目前仅取消直接进程；脱离进程组的后代不能保证终止。现有远控禁用开关仍在执行前检查。

桥接各会话输出缓存与磁盘日志上限默认 2 MiB，可配置到 32 KiB～8 MiB；旧游标或溢出明确报告缺口，继续持续读取。桥接未收到的断线输出仍无法补回。日志保留策略沿用既有有界存储，不新增无界远端日志。

`execution.json` 私有持久化永久配置；租约、计时器、WebSocket 都是进程内状态。命令记录包含请求期限、探针返回截止时间、超时与不确定状态。审计只记录 ID、状态、耗时和配置范围，不记录密钥或命令正文；离线诊断导出包含期限信息，参见 [诊断说明](DIAGNOSTICS.md)。没有 cgroup 强制内存隔离，不能宣称绝对防 OOM。

## 升级与验收

保留官方 Release 二进制下载／服务启动／安装脚本的发行方式。源补丁增加 `0003-execution-protection.patch` 与 overlay，并由原构建流水线验证、组装；无需在每台被控设备构建源码。先隔离测试匹配版本，再切换真实面板、桥接和目标探针。当前开发提交未发布 Release、未切换用户生产服务。

必测：未协商拒绝普通执行；5/8/10/12 边界；多 Key 共享上限；租约到期但命令不被杀；查询与心跳不续期；重复命令不续期；长任务显式期限；满槽中断／维护；过期策略重新协商；降低上限不杀旧任务；断线时探针期限仍生效；输出截断不阻塞；配置重启持久化；旧探针不能被报为就绪。
